## 2. 数据规模实测

### 引用上下文识别格式

| 划分 | JSONL行数 | 段落句子数 | 标为上下文的句子数 |
|---|---:|---:|---:|
| Train | 2,143 | 15,882 | 2,417 |
| Dev | 317 | 2,134 | 341 |
| Test | 606 | 4,107 | 677 |
| 合计 | 3,066 | 22,123 | 3,435 |

每行主要字段为：

- `sentences`：包含引用标记的段落，按句切分
- `labels`：与句子一一对应的0/1标签，1表示属于该引用的上下文
- `<CITATION_MARKER>...</CITATION_MARKER>`：目标引用位置

### MultiVerS格式

| 划分 | Claim数 |
|---|---:|
| Train | 2,141 |
| Dev | 316 |
| Test | 606 |
| 合计 | 3,063 |

按论文的三分类映射后，各划分分布如下：

| 划分 | ACCURATE | NOT_ACCURATE | IRRELEVANT |
|---|---:|---:|---:|
| Train | 1,368 | 630 | 143 |
| Dev | 191 | 101 | 24 |
| Test | 386 | 170 | 50 |
| 合计 | 1,945 | 901 | 217 |

每条claim主要字段为：

- `id`：引用实例编号
- `claim`：转换后的引用上下文
- `evidence`：被引文档编号、人工证据句编号和标签
- `cited_doc_ids`：候选被引文档编号

`corpus.jsonl`实测包含8,515条候选文档、29,365个句子。它不只是100篇核心被引论文，而是为检索任务准备的候选文档语料。

原始 `annotations.zip` 中每条引用实例包含：`citing_paragraph`、`citation_context`、`evidence_segments`、`marker_span` 和 `label`。仓库还把论文中的82条 `INDIRECT` 拆成了 `INDIRECT` 48条与 `INDIRECT_NOT_REVIEW` 34条，三分类转换时两者均应合并到 `ACCURATE`。

## 3. 发现的数据差异

论文报告3,063条引用实例，发布版MultiVerS文件也正好包含3,063条；但引用上下文识别的train/dev/test原始文件合计3,066行，多出3行，其中训练集相差2行、验证集相差1行。

这不一定是数据错误，可能来自多引用标记拆分、重复实例过滤或格式转换。但正式复现前必须追踪这3行，避免上下文模型和最终分类模型使用不同样本集合。

## 4. 代码与环境审计

官方依赖包括：

- Python旧版本生态
- `torch==1.7.1`
- `transformers==4.2.2`
- `pytorch-lightning==1.2.1`
- `numpy==1.19.4`
- `scikit-learn==0.23.2`
- `spacy==2.3.5`

当前机器环境：

- Python 3.13.5
- PyTorch 2.9.1 CPU版
- `transformers`未安装
- 物理显卡：NVIDIA GeForce RTX 3050 Laptop GPU，4 GB显存
- 当前PyTorch无法使用CUDA

结论：官方环境不能直接安装到当前Python 3.13解释器。下一步应新建隔离环境，优先选择Python 3.8或3.9；先运行官方检查点的小批量推理，再评估4 GB显存能否支持训练。完整训练可能需要实验室服务器或云端GPU。

另一个更直接的代码风险是：仓库提供的claims文件仍保留 `CONTRADICT`、`NOT_SUBSTANTIATE`、`ETIQUETTE` 等细粒度标签，而 `data_verisci.py` 的外部标签读取只接受 `ACCURATE`、`NOT_ACCURATE` 和 `NOT_ENOUGH_INFO`。其中IRRELEVANT不能只改名后继续放在 `evidence` 中；按读取逻辑，应保留其 `cited_doc_ids`，但删除对应 `evidence` 条目，由程序将其作为无证据文档生成NOT ENOUGH INFO。README没有给出这一步，直接训练很可能发生标签错误。

已编写 `convert_citation_labels.py` 补足该步骤，并对3,063条claim中的6,131个显式证据集合运行仓库 `make_label` 读取校验，转换后显式标签仅剩 `ACCURATE` 与 `NOT_ACCURATE`；3个IRRELEVANT显式证据集合被正确改为隐式NEI结构。

## 5. 当前可向项目组汇报的判断

1. 数据、代码和模型均确实公开，具备baseline复现条件。
2. 数据存在“原始上下文3,066行、最终claim 3,063条”的小差异，已经定位为待核查项。
3. 代码栈较旧且缺少三分类标签预处理，不能把“仓库公开”直接等同于“一键可运行”。
4. 当前本机可做数据审计和CPU小样本处理；模型推理需先重建环境，完整训练需进一步评估显存。
5. 首轮应先完成官方检查点推理，不应直接从头训练。
