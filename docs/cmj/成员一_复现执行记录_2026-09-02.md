## 5.3 MultiVerS 分类管道冒烟（09-05追加）

### 权重获取阻塞记录

MultiVerS 官方 checkpoint 两个来源均无法在本机网络环境快速获取：

| 来源 | 状态 | 实测 |
|---|---|---|
| S3（scifact.ckpt / healthver.ckpt，各4.89GB） | 可连接但极慢 | 单线程0.01 MB/s、4线程并发0.03 MB/s，全量下载需数十小时 |
| Google Drive（Sarol最佳模型，约5.25GB） | 不可达 | 连接超时 |
| HuggingFace 镜像 | 无此模型 | 搜 multivers/scifact/wadden/citation-integrity 均无官方权重 |

结论：在本机网络下无法在可接受时间内取得官方 checkpoint，属环境阻塞而非代码问题。

### 替代验证：管道冒烟（随机分类头）

为把“BM25 -> MonoT5 -> MultiVerS 分类”三段链路在本机跑通并留下可复现记录，使用：

- 编码器：`allenai/longformer-base-4096`（HuggingFace 官方权重，经 hf-mirror 下载，569.6MB）；
- 分类头：按官方 `model.py` 的 `label_classifier` 结构（Dropout + 2层MLP，hidden->hidden->3，GELU）**随机初始化**；
- 标签映射：官方 `predict.py` decode 口径 {0: NOT_ACCURATE, 1: NEI, 2: ACCURATE}；
- 输入：claim + 每句证据（`</s>` 分隔，官方 data.py 构造方式），global attention 覆盖 claim 与特殊token；
- 证据来源：`monot5_30_eval_result.json` 的 top-5 证据句（即真实BM25+MonoT5检索产物）；
- 设备：CPU（arm4r_py39 环境，Python 3.9.25，torch 2.8.0+cpu，transformers 4.57.1）。

命令：

```text
python work\run_multivers_pipeline.py --n_claims 30 --top_k 5
```

结果：

- 30条 claim、150条 top-5 证据句全部前向完成；
- 推理耗时：33.1秒（平均约1.1秒/条）；
- 证据句中含人工标注的：15句（gold 分布：NOT_ACCURATE 5 / ACCURATE 10；该15句为MonoT5 top-5 中命中 gold 的部分，对应30条中5条 rank1 命中的同一来源）；
- 预测分布：随机分类头输出全部落在 ACCURATE（概率约0.34/0.32/0.34，符合随机初始化预期）；
- 结果文件：`outputs\multivers_pipeline_smoke_result.json`。

⚠️ 重要：本结果为**管道冒烟验证**，分类头未经训练，输出概率与标签**无指标意义**，只证明“claim+证据 -> tokenize -> Longformer 编码 -> 三分类输出 -> 结果落盘”的代码链路可运行。获得官方 checkpoint 后，把 `run_multivers_pipeline.py` 中的编码器替换为 `MultiVerSModel.load_from_checkpoint()`（官方 predict.py 入口）即可产出有意义的预测。

## 5.4 官方 scifact.ckpt 下载与真实推理（09-07追加）

### 5.4.1 权重获取：SakuraCat 代理 + 8线程分片下载

本机直连 S3 限速 0.01–0.03 MB/s 无法接受，改用 SakuraCat 代理（系统代理 127.0.0.1:7897）后：

- 代理测速：S3 单线程 0.63 MB/s、4线程 0.94 MB/s（直连对照快 21 倍+）；
- 编写 `work\download_scifact_ckpt.py`：8线程 Range 分片、每段断点续传 + 失败重试8次 + 段大小校验，下载后合并并与 Content-Length 比对；
- 实测：峰值 11.5 MB/s、平均约 8 MB/s，**19:26–19:38 约12.5分钟完成**；
- 校验：拼接后 **5,253,770,098 字节** 与 S3 HEAD Content-Length **完全一致** ✅；
- 产物：`work\checkpoints\scifact.ckpt`（日志 `work\checkpoints\download_scifact.log`）；
- 同时经 hf-mirror 下载 Longformer-large-4096 编码器（1662.2MB，`work\longformer-large-4096\`）。

### 5.4.2 推理环境补齐

arm4r_py39 原本缺两个依赖（清华源 pip 安装）：

| 包 | 版本 | 用途 |
|---|---|---|
| pytorch-lightning | 2.6.0 | checkpoint 反序列化（旧版 PL 1.x pickle 的 `_gpus_arg_default` 等属性在 2.x 已移除，加载前需 monkey-patch 补回） |
| sentencepiece | 0.2.2 | T5Tokenizer（MonoT5 全量重排需要） |

### 5.4.3 官方推理实现（work\run_multivers_official.py）

- 加载：`torch.load(scifact.ckpt)` → state_dict 544 项；编码器 `encoder.*`（Longformer-large，hidden=1024），分类头 `label_classifier._linear_layers.{0,1}.*`；
- 词表对齐：官方词表 **50275**（比 Longformer 标准 50265 大 10，训练时扩增），`resize_token_embeddings(50275)` 后加载权重；
- 分类头：官方 FeedForward 结构（Linear→GELU→Dropout→Linear），key 名 `_linear_layers.N.*` 映射到本脚本 `fcN.*`；
- 输入构造：claim + top-k 证据句 `</s>` 拼接（与冒烟一致），global attention 覆盖 claim 与特殊 token；
- 设备：CPU，约 3.2s/条（Longformer-large，输入 token 不长）。

命令：

```text
python work\run_multivers_official.py --n_claims 30 --top_k 5 --out multivers_official_30_result.json
python work\run_monot5_full_eval.py                                # 全量 606 条 BM25+MonoT5
python work\run_multivers_official.py --n_claims 606 --top_k 5 --evidence_file outputs\monot5_full_eval_result.json --out multivers_official_full_result.json
python work\eval_multivers_official.py outputs\multivers_official_full_result.json
```

### 5.4.4 结果

**MonoT5 全量 606 条**（BM25 粗选 top10 → MonoT5 精排）：rank1 命中 106/606（17.5%）、rank@5 命中 311/606（51.3%），耗时 1084.9s。

**MultiVerS 官方权重**：

| 评测范围 | 预测分布 NA/NEI/ACC | 准确率 | 耗时 |
|---|---:|---:|---:|
| 30 条 × top-5 | 0/23/7 | 0.200 | 99.3s |
| 全量 606 条 × top-5 | 9/489/108 | **0.328**（199/606） | 1951.4s |

全量混淆矩阵：ACCURATE gold 386 → 判对 85 / 误判 NEI 294；NOT_ACCURATE gold 100 → 判对 1 / 误判 NEI 82；NEI gold 120 → 判对 113。

**结论**：官方 scifact.ckpt 为 SciFact 任务预训练模型、未在 Sarol 微调，零样本迁移到 Sarol 呈强保守倾向（80.7% 判 NEI），准确率 0.328 属合理预期。**本周第 4 项“跑通流程”已在真实权重上端到端闭环并产出可复现指标**；论文 0.59/0.52 需 Sarol 微调模型（Google Drive 不可达）或本机 GPU 微调。
