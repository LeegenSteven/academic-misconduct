# 第二次会议四分钟发言稿

我负责的是引用语义识别和主数据集。这一周我的启动比原计划慢，所以我先集中完成了核心方法、公开数据和代码的核验，目前还没有进入正式训练阶段。

项目文档指定的核心工作是Sarol等2024年的引用完整性识别。这个任务的输入不是引用次数，而是引用论文中的引用上下文和被引论文中的原始证据。原方法首先用BM25召回候选证据句，用MonoT5重排序，然后把前20个证据句和引用句输入MultiVerS，输出ACCURATE、NOT_ACCURATE和IRRELEVANT三类。

数据方面，我已经把官方仓库完整获取并做了初步审计。论文报告3,063条真实引用，MultiVerS发布格式中训练、验证、测试分别为2,141、316和606条，合计也是3,063条。引用上下文识别的原始文件则有3,066行，比最终分类数据多3行，可能是多引用拆分或格式转换过滤造成的，我会在复现前进一步核对。候选语料文件实测包含8,515篇文档和29,365个句子。

效果方面，直接使用引用句作为上下文的F1是0.94，反而略高于PubMedBERT的0.93。真正的瓶颈是证据检索，BM25加MonoT5取前20句时只能召回大约53%的人工证据。最终MultiVerS最好结果是micro-F1 0.59、macro-F1 0.52；如果直接使用人工证据，macro-F1可以提高到0.75。因此我认为第一优先级应该是跑通官方baseline并分析证据检索，而不是立即更换成更大的分类模型。

我还发现两个需要项目组讨论的问题。第一，原论文把INDIRECT，也就是内容可能正确但引用的不是原始来源，合并进了准确类。对于治理项目，这类情况可能仍然需要提示，建议保留细粒度标签。第二，数据主要来自生物医学领域，后续迁移到其他学科必须做外部验证。

代码方面，官方依赖是Torch 1.7.1和Transformers 4.2.2等较旧版本，而当前机器是Python 3.13和CPU版PyTorch，不能直接运行。另外，公开claim文件还是细粒度标签，但训练代码只接受三分类，README缺少这一步转换。我已经补写转换脚本，对3,063条claim和6,131个显式证据集合完成读取校验。下一步是建立Python 3.8或3.9隔离环境，用官方检查点跑10到30条样例推理，同时核对那3条数据差异。下次会议我可以提交环境记录和第一批模型输出。
