# 学术引文不端项目：成员一阶段调研与会议汇报

会议时间：2026年8月31日 16:30  
负责方向：引用语义识别与主数据集

## 一、当前阶段结论

本方向可以先形式化为一个跨文档证据核验任务：输入引用论文中的引用上下文，以及被引论文全文；先从被引论文检索相关证据句，再判断引用内容是否得到实质支持。

首个建议复现的 baseline 是 Sarol 等（2024）的公开方案：

`引用句 -> BM25召回候选句 -> MonoT5重排序 -> 取Top-20证据句 -> MultiVerS三分类`

输出三类语义风险信息：`ACCURATE`、`NOT_ACCURATE`、`IRRELEVANT`。该方法有公开论文、数据、代码和模型，适合作为项目路线一的起点，但当前效果有限，主要瓶颈在被引证据检索。

## 二、核心论文与资源

核心论文：Maria Janina Sarol et al. (2024), *Assessing citation integrity in biomedical publications: corpus annotation and NLP models*, Bioinformatics 40(7), btae420。  
DOI：10.1093/bioinformatics/btae420  
代码与数据：https://github.com/ScienceNLP-Lab/Citation-Integrity

已核验的公开资源：

- 原始数据：`Data/train.jsonl`、`dev.jsonl`、`test.jsonl`
- MultiVerS格式数据：claims train/dev/test和corpus文件
- 代码：引用准确性分类、BM25+MonoT5检索、MultiVerS训练与预测
- 数据按100篇核心被引论文划分：训练70篇/2,141条、验证10篇/316条、测试20篇/606条，各划分之间没有核心被引论文交叉

## 三、数据与标签

### 3.1 数据规模

| 项目 | 数量 |
|---|---:|
| 核心被引论文 | 100篇 |
| 真实引用实例 | 3,063条 |
| 引用上下文句 | 3,420句 |
| 人工标注证据句 | 3,791句 |
| 平均每条引用的上下文句 | 1.12句 |
| 平均每条引用的证据句 | 1.24句 |

原始标注中，准确引用1,863条，占60.82%；含错误或其他问题的引用1,200条，占39.18%。这里的1,200条仍包含82条 `INDIRECT`；在三分类建模时，这82条才被移入 `ACCURATE`，因此不能把论文的原始“准确/错误”统计和模型三分类统计混用。

### 3.2 细粒度标签

| 标签 | 数量 | 含义 |
|---|---:|---|
| ACCURATE | 1,863 | 引用内容与被引论文证据一致 |
| CONTRADICT | 92 | 引用内容与被引论文结论矛盾 |
| NOT_SUBSTANTIATE | 243 | 被引论文不足以支撑引用中的断言 |
| IRRELEVANT | 217 | 被引论文没有相关信息 |
| MISQUOTE | 38 | 错误转述或引用 |
| OVERSIMPLIFY | 111 | 过度简化，导致原意变化 |
| INDIRECT | 82 | 内容可追溯，但被引论文并非原始来源 |
| ETIQUETTE | 417 | 引用规范或归属方面存在问题 |

### 3.3 三分类映射

| 项目输出 | 原始标签映射 | 数量 |
|---|---|---:|
| ACCURATE | ACCURATE + INDIRECT | 1,945 |
| NOT_ACCURATE | CONTRADICT + NOT_SUBSTANTIATE + MISQUOTE + OVERSIMPLIFY + ETIQUETTE | 901 |
| IRRELEVANT | IRRELEVANT | 217 |

需要讨论的一点：原论文为降低建模难度，把 `INDIRECT` 合并到 `ACCURATE`。对于治理项目，“内容正确但引用了非原始来源”仍可能是需要提示的学术规范问题，因此建议保留原始细粒度标签，不要在数据层面永久合并。

## 四、原方法流程与结果

### 4.1 引用上下文识别

引用标记所在句称为 citance。简单地把 citance 作为上下文，F1为0.94；微调PubMedBERT扩展上下文，F1为0.93，没有超过简单基线。因此首轮复现可以直接使用引用句，减少一个模型环节。

### 4.2 被引证据检索

使用引用上下文作为查询，BM25先召回60个候选句，MonoT5重排序，再取Top-5、Top-10或Top-20。以引用句作为查询时：

| 指标 | 结果 |
|---|---:|
| Recall@5 | 0.28 |
| Recall@10 | 0.40 |
| Recall@20 | 0.53 |
| MRR（Top-20） | 0.32 |

即使取Top-20，约一半人工标注的相关证据句仍没有被召回，这是目前最明确的性能瓶颈。

### 4.3 三分类

MultiVerS接收引用句和检索到的证据句，输出三分类结果。最佳配置为Top-20证据句：

| 指标 | 结果 |
|---|---:|
| ACCURATE F1 | 0.69 |
| NOT_ACCURATE F1 | 0.43 |
| IRRELEVANT F1 | 0.42 |
| Micro-F1 | 0.59 |
| Macro-F1 | 0.52 |

GPT-4少样本方法的Micro-F1为0.65，但Macro-F1只有0.45，尤其 `NOT_ACCURATE` F1仅0.09。因此它更倾向判断为准确，暂不适合作为发现错误引用的主模型。

使用人工标注证据句时，MultiVerS可达到0.73 Micro-F1和0.75 Macro-F1，进一步说明提升证据检索比盲目更换分类器更优先。

## 五、可复现性与局限

### 可直接复用

- 数据、代码和最佳模型公开，任务定义与本项目路线一基本一致。
- 三分类输出可以转换为每条引用的语义风险特征。
- 数据已提供MultiVerS结构，但当前claim文件仍保留细粒度标签，需先补充三分类转换步骤。

### 当前局限

1. 数据集中于生物医学领域，迁移到其他学科前必须做外部验证。
2. 证据句检索Recall@20约0.53，后级分类器经常看不到正确证据。
3. 证据句和准确性标签的标注者一致性仅达到一般水平，任务本身存在主观性。
4. 论文排除了证据位于表格、图片和补充材料的情况。
5. 三分类压缩了错误类型，不完全满足“识别后治理和解释”的需要。
6. 公开代码依赖较早版本的模型与训练库，正式复现前需要单独核验环境。
7. claim文件包含 `CONTRADICT`、`ETIQUETTE` 等细粒度标签，而训练代码只接受三分类结构；其中IRRELEVANT还必须转成“候选文档存在、evidence条目为空”的隐式NEI结构。README缺少这一步，直接运行可能报错。

## 六、下一步实验建议

目前已补充细粒度到三分类的转换脚本，并对3,063条claim中的6,131个显式证据集合通过仓库读取器校验。IRRELEVANT对应的3个显式证据集合已按代码语义转为隐式NEI结构。下一阶段不立即改模型，先复现和定位误差：

1. 在已完成转换脚本的基础上，随机抽查30条样本并补齐字段字典。
2. 固定引用句作为上下文，复现BM25+MonoT5的Recall@5/10/20。
3. 先运行官方检查点推理，再决定是否从头训练MultiVerS。
4. 输出混淆矩阵，重点分析 `NOT_ACCURATE` 被判成 `ACCURATE` 的样本。
5. 对比“标题+摘要”“Top-5”“Top-20”和人工证据四种输入。
6. 保留细粒度标签，为后续治理解释提供依据。

下一周可验收产出：数据字段表、30条样本核验记录、环境与运行说明、官方模型10至30条样例推理结果，以及复现中的阻塞项清单。

## 七、会议汇报结构（约4分钟）

### 1. 任务理解（30秒）

我负责的是单条引用的语义完整性识别，目标不是看引用次数，而是比较引用上下文和被引论文证据，判断它属于准确、不准确还是无实质关联。

### 2. 已完成进展（90秒）

我已定位并核验项目指定的Sarol 2024核心论文、3,063条引用数据、代码和模型。数据来自100篇高被引生物医学论文，包含引用上下文、被引证据和细粒度错误标签。原方法先用BM25和MonoT5从被引全文检索证据，再用MultiVerS进行三分类。

### 3. 初步判断（60秒）

最佳模型Micro-F1为0.59、Macro-F1为0.52。当前瓶颈不是上下文扩展，而是证据检索：Top-20只能召回约53%的人工证据。另一个需要讨论的问题是，原论文把间接引用合并进准确类，这对治理场景可能过于宽松。

### 4. 下一步（60秒）

我建议先复现官方基线，不立即增加大模型。下一周先完成数据字段审计、30条样本核验和官方模型小规模推理，再根据错误分析决定优先改进检索器还是分类器。

## 八、可能追问及回答

**为什么推荐该论文做baseline？**  
它与项目三分类目标最接近，并且论文、数据、代码和模型均公开，能够形成可复查的起点。

**PubMedBERT为什么没有作为最终分类器？**  
论文用它做引用上下文句识别，但简单使用引用句已经达到0.94 F1，略高于PubMedBERT的0.93。最终三分类采用能够处理长证据输入的MultiVerS。

**为什么不直接用GPT-4？**  
GPT-4总体准确类效果较好，但对最重要的错误类召回很差，`NOT_ACCURATE` F1只有0.09，容易漏掉错误引用。

**本项目最值得先改进哪里？**  
先改证据检索。使用人工证据时分类Macro-F1可达0.75，而自动检索只有约0.52，差距很明显。

**这个数据能直接用于所有学科吗？**  
不能。它主要来自生物医学开放全文，只适合作为初始基线，跨学科应用需要新的测试集或小规模人工标注验证。

**和成员二如何分工？**  
成员一负责Sarol主数据集、字段标签、原方法和复现入口；成员二负责SciCiteVal及其他BERT、LLM方法横向比较。两边最后在统一的输入、输出和指标表中衔接。
