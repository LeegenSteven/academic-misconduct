## 1. 任务设置

| 项 | 值 |
|---|---|
| 数据 | Sarol Dev 集（converted-three-class/claims-dev.jsonl，316 条） |
| 权重 | scifact.ckpt（MultiVerS 官方 SciFact 预训练，4.893GB，SakuraCat 代理下载校验一致） |
| 权重性质 | **跨数据集迁移**（SciFact 训练 → Sarol 评测，非 Sarol 微调） |
| 编码器 | Longformer-large-4096（hf-mirror 本地目录） |
| 设备 | CPU（arm4r_py39，torch 2.8.0+cpu），约 8.6s/条（金标准输入句子多、序列长） |
| 输入构造 | claim + 证据句 `</s>` 拼接；global attention 覆盖 claim 与特殊 token |
| 标签映射 | {0: NOT_ACCURATE, 1: NEI, 2: ACCURATE}（官方 predict.py 口径） |
| gold 聚合 | 证据含 NOT_ACCURATE → NOT_ACCURATE；全 ACCURATE → ACCURATE；无证据 → NEI |

**两组输入**：
- **A 金标准证据块**：全部 gold evidence 句子（人工标注的支撑/反驳句）作为输入
- **B BM25 候选块**：按被引文献分组 BM25 检索的 top-20 句子作为输入（句子级）

## 3. 检索口径说明（任务2a）

| 口径 | 评测范围 | Recall@5 | Recall@10 | Recall@20 | 评价单位 |
|---|---:|---:|---:|---:|---|
| 统一语料（29,365 句） | 测试集 606 条 | 0.150 | 0.212 | 0.276 | 句子 |
| 按被引文献分组（8,515 文档） | 测试集 606 条 | 0.221 | 0.314 | 0.430 | 句子 |

- 样本数：测试集 606 条 claim；检索范围：统一语料 = 全部 29,365 句 / 分组 = 仅该 claim 被引文献的句子；
- 评价单位：**句子级**（corpus 的 sentence_index）；分组 top-20 即 Dev 对照中 B 组的候选来源（句子级证据块）；
- 实现：纯 Python BM25（无 Pyserini/Lucene），k1=1.5、b=0.75。

## 4. MonoT5 重排前后对比（任务2b，30 条样本）

固定同一候选集（按被引文献分组 BM25 top-10），比较首位命中率：

| 设置 | rank1 命中 | 命中率 |
|---|---:|---:|
| 重排前（BM25 原始分数排序） | 5/30 | 16.7% |
| 重排后（MonoT5 true-logprob 排序） | 5/30 | 16.7% |

- 同时命中 3 条；仅 BM25 命中 2 条；仅 MonoT5 命中 2 条；
- 结论：小样本（30 条）上重排**不改变首位命中总数**，但**改变了命中的具体样本**（交集 3/5）；重排的收益主要体现在 top-5/top-10 覆盖与排序质量，单看 rank1 在 30 条规模上无提升。

## 5. 当前结论

1. **证据检索不是主要瓶颈**：金标准证据输入（0.263）准确率反而低于 BM25 top-20 输入（0.339），说明检索输入未拖累分类，错误主要来自分类环节。
2. **模型强 NEI 倾向是主要问题**：两组均有 80%+ 判 NEI；NOT_ACCURATE 类几乎全漏（64 条中仅 1 条判对）——SciFact 预训练模型对 Sarol 数据的迁移能力不足，这是与论文 0.59/0.52 差距的核心原因。
3. 金标准输入序列更长（全部证据句），可能进一步偏离 SciFact 训练分布，导致 NEI 倾向更强（91.5%）。
