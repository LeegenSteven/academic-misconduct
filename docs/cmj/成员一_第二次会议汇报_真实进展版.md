# 学术引文不端项目：成员一第二次会议汇报（真实进展版）

会议时间：2026年8月31日 16:30  
负责方向：引用语义识别与主数据集

## 一、本周完成的工作

本周的工作主要分为三部分：精读核心论文、获取并理解公开数据、核对论文与公开数据是否一致。目前尚未完成模型复现和训练。

### 1. 精读核心论文

我精读了 Sarol 等人在2024年发表的核心论文 *Assessing citation integrity in biomedical publications*，重点梳理了以下内容：

1. 研究任务不是统计一篇论文被引用了多少次，而是比较“引用论文怎么描述被引研究”和“被引论文实际提供了什么证据”。
2. 数据包含100篇核心被引论文，以及3,063条真实引用实例。训练集、验证集和测试集分别为2,141条、316条和606条。
3. 原始标注包括 `ACCURATE`、`CONTRADICT`、`NOT_SUBSTANTIATE`、`IRRELEVANT`、`MISQUOTE`、`OVERSIMPLIFY`、`INDIRECT` 和 `ETIQUETTE` 等细粒度标签。
4. 建模时将细标签合并为三类：`ACCURATE` 1,945条、`NOT_ACCURATE` 901条、`IRRELEVANT` 217条。
5. 原方法的主要流程是：

   `引用上下文 -> BM25召回 -> MonoT5重排序 -> Top-20候选证据 -> MultiVerS三分类`

6. 论文中证据检索的 Recall@20 约为0.53，最终MultiVerS的Micro-F1为0.59、Macro-F1为0.52；使用人工证据时Macro-F1可提高到0.75。因此，证据检索是整个流程的主要瓶颈。

### 2. 下载并整理公开数据

我已经获取作者公开仓库中的三类主要数据：

- `annotations.zip`：最原始的人工标注，每条引用包含完整引用段落、引用上下文、人工证据、引用标记位置和标签。
- 外层 `train.jsonl`、`dev.jsonl`、`test.jsonl`：用于引用上下文识别，字段主要是段落句子和0/1上下文标签。
- `multivers-format`：包含 `claims-train/dev/test.jsonl` 和 `corpus.jsonl`，用于证据检索和最终分类。

公开数据及代码保存在：

`D:\引文不端\项目数据与代码\Citation-Integrity-main`

### 3. 使用脚本工具进行数量核对

数量较大，因此没有人工逐条计数，而是使用脚本读取全部数据，再对少量真实样本进行人工语义核验。

全量计数形成了三方交叉验证：

- 论文报告：3,063条引用实例。
- `annotations.zip`：Train 2,141个、Dev 316个、Test 606个引用JSON，合计3,063个。
- `claims-*.jsonl`：Train 2,141行、Dev 316行、Test 606行，合计3,063行。

脚本还读取了每条原始标注中的 `label`。仓库将论文中的82条 `INDIRECT` 拆成48条 `INDIRECT` 和34条 `INDIRECT_NOT_REVIEW`；将两者重新合并后，各细粒度标签的数量与论文一致。

这里还厘清了两个统计口径：

- `corpus.jsonl` 的8,515行是候选文献语料块，不是8,515篇完整被引论文；其中共有29,365个句子。
- 逐个统计 `claims` 中的 `evidence` 会得到证据集合数量，而不是引用实例数量。一条claim可以有多组证据，因此不能把证据标签次数直接当作论文的类别分布。

## 二、发现的数据差异

外层引用上下文识别文件共有3,066行：Train 2,143行、Dev 317行、Test 606行。最终 `claims` 和原始人工标注则共有3,063条：Train 2,141条、Dev 316条、Test 606条。因此训练集相差2条，验证集相差1条。

进一步检查后得到以下结论：

1. 多出的3行不是三条完全相同的重复数据。
2. GitHub提交记录显示，外层 `train/dev/test.jsonl` 于2024年3月19日上传；`annotations.zip` 和 `claims-*.jsonl` 于2025年2月8日另行上传。
3. 两类文件不是同一次导出的同一数据版本。较合理的解释是，作者在形成后期正式标注和MultiVerS数据时进行了清洗、过滤或重新整理，但没有同步更新早期上下文识别文件。
4. 外层文件没有样本ID，仓库也没有提供两个版本的映射表、生成脚本或过滤说明，因此目前无法确定具体删去了哪三条以及采用了什么规则。

这一差异不会改变最终分类数据的3,063条规模，但会影响引用上下文识别模型与最终分类模型是否使用完全相同的样本集合，属于后续复现时需要记录的数据版本问题。

## 三、真实样本核验

我已经开始直接打开 `annotations.zip` 中的真实JSON，按照“先读引用主张、再读证据、最后看标签”的顺序核验。

已完成的样本A中，引用主张是“使用吸入性糖皮质激素会降低ACE2表达”；被引论文证据是“ICS使用与较低的ACE2和TMPRSS2表达相关”。两者含义基本一致，人工标签为 `ACCURATE`，个人核验同意该标签。

通过这个样本，我确认了主要字段的含义：

- `citing_paragraph`：引用所在的完整段落。
- `citation_context`：需要核查的引用主张。
- `evidence_segments`：从被引论文中标出的证据。
- `marker_span`：目标引用编号及其位置。
- `label`：人工标注的引用完整性类别。

目前完成的是全量数量核对和少量样本语义核验，不能表述为人工逐条检查了3,063条。

## 四、目前形成的判断

1. 论文、原始标注、MultiVerS输入和代码均已公开，具备建立baseline的基本条件。
2. 最终分类数据的3,063条规模和标签分布可以与论文相互验证。
3. 仓库同时保留了两个不同时间发布的数据版本，引用上下文文件与最终claim相差3条，复现时必须固定版本和统计口径。
4. 原论文把 `INDIRECT` 合并入 `ACCURATE`。对于学术不端治理场景，这种“内容基本正确但引用的不是原始来源”的情况仍有提示价值，后续不应只保留三分类结果。
5. 当前最值得优先复现和分析的是证据检索，因为分类器只有先看到正确证据，才可能正确判断引用是否准确。

## 六、会议口头汇报稿（约4分钟）

我负责的是引用语义识别和主数据集。本周我主要完成了三项工作：精读核心论文、下载并理解公开数据，以及核对论文和数据是否一致。目前还没有进入模型训练阶段。

首先，我精读了Sarol等人在2024年发表的引用完整性论文。这个任务不是看引用次数，而是比较引用论文中的主张和被引论文中的原始证据，判断引用是否准确。论文数据包括100篇核心被引论文和3,063条真实引用实例。原始标注有准确、矛盾、证据不足、无关、错误转述、过度简化、间接引用和引用规范问题等细标签；建模时再合并为准确、不准确和无关三类。

原方法先提取引用上下文，用BM25召回候选证据句，再用MonoT5重排序，取前20个候选证据输入MultiVerS进行三分类。论文中证据检索的Recall@20只有大约0.53，最终模型的Micro-F1为0.59、Macro-F1为0.52；如果直接使用人工证据，Macro-F1可以提高到0.75。因此我目前的判断是，主要瓶颈在证据检索，而不只是最终分类器。

数据方面，我已经下载了三部分公开资源。第一是最原始的人工标注 `annotations.zip`；第二是用于引用上下文识别的train、dev和test文件；第三是用于MultiVerS的claims和corpus文件。我借助脚本工具进行了全量计数，并打开真实JSON做人工核验。论文、原始标注和claims三者都能核对到3,063条，训练、验证和测试分别为2,141、316和606条。原始标签在合并仓库拆分的两种INDIRECT后，也能与论文数字对应。

核对过程中发现一个数据版本问题。外层引用上下文文件合计是3,066行，比正式claim多3行，其中训练集多2行、验证集多1行。继续检查GitHub记录后发现，外层上下文文件在2024年3月上传，而annotations和claims是在2025年2月另行上传，两者不是同一个时间的数据版本。公开仓库没有提供样本ID映射和过滤说明，所以目前只能确认这是版本不一致，还不能断言具体三条为什么被过滤。

我还打开了一条真实人工标注进行核验。该样本的引用主张是使用吸入性糖皮质激素会降低ACE2表达，被引证据也报告ICS与较低ACE2表达相关，因此我同意它的ACCURATE标签。这个过程也帮助我明确了引用段落、引用上下文、证据片段和标签各自的作用。

下一步我会先把人工核验扩展到10至30条，覆盖主要错误类型；然后建立隔离环境，优先跑通官方检查点的小样本推理，并记录模型输入、输出和错误类型。目前模型尚未复现，本次完成的是论文理解、数据获取、全量数量核对和初步样本核验。

## 七、可能被追问的问题

**为什么3,066和3,063对不上？**  
它们是不同时间发布、用于不同环节的数据版本。现有证据支持“后期正式数据经过调整但旧版上下文文件未同步更新”，但仓库没有公开具体三条的映射和过滤规则。

**你是不是人工检查了3,063条？**  
不是。3,063条的数量和标签分布由脚本全量统计；人工负责理解字段并抽查真实样本的语义。

**8,515是不是被引论文数量？**  
不是。8,515是 `corpus.jsonl` 的语料块数量，不能等同于8,515篇论文。

**模型跑通了吗？**  
还没有。目前完成了论文精读、数据获取和数据核验，下一步才是隔离环境和官方检查点的小样本推理。

**为什么先关注证据检索？**  
因为自动检索只能找到约53%的人工证据，而使用人工证据时分类效果明显提高，说明分类器经常是因为没有看到正确证据而判断错误。
