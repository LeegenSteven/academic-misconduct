## 边界规则

**`cmj/` 和 `ly/` 是私人工作区。** 自己目录里怎么组织都行，另一个人不 review、不改动，也不从对方目录里 import。这样两个人可以并行试错而不互相阻塞。

**`shared/` 是公共层，改动会影响对方。** 放进去的东西要满足至少一条：

- 同一段逻辑在两个私人目录里各写了一遍（重复是抽取的信号，不是提前抽象的理由）
- 两边都要读同一份数据或同一张常量表（比如期刊名单、机构映射、字段枚举）
- 需要保证两边口径一致（比如"什么算一次撤稿"的判定函数——口径不一致会让两边的统计数字对不上）

**不要提前往 `shared/` 塞"通用框架"。** 两个人还在探索阶段时，抽象出来的接口大概率是错的，改接口比改两份副本更麻烦。

## 进 `shared/` 的流程

1. 在群里说一声你要动 `shared/` 的哪个文件
2. 改完确保另一个人的代码还能跑
3. 破坏性改动（改函数签名、改返回值结构）要单独提一个 commit，commit message 里写清楚 `BREAKING:`
