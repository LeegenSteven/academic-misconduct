## 二、等价性未通过根因分析

### 2.1 核心 bug：loss 归一化不一致

**标准版行为**（transformers 5.8.0 `fixed_cross_entropy`）：
- 当 `num_items_in_batch` 不为 None 时，使用 `reduction="sum"`，然后除以 `num_items_in_batch`
- `num_items_in_batch` 在梯度累积时是**整个累积周期的有效 token 总数**
- 例如 accum4_tail 第一个 microbatch：supervised_tokens=10，但 num_items_in_batch=37（4 个 microbatch 的监督 token 总和）

**优化版原行为**（修复前）：
- 使用 `reduction="mean"`，对当前样本的监督 token 取平均
- `self.model_accepts_loss_kwargs = False`，导致 Trainer 不传入 `num_items_in_batch`
- 然后 Trainer 自动除以 gradient_accumulation_steps

**数学差异**：
- 标准版：每个 microbatch loss = sum(token_losses) / total_cycle_tokens
- 优化版：每个 microbatch loss = mean(token_losses) / accumulation_steps
- 当各样本监督 token 数不同时，两者不等价

**实测数据**（accum4_tail micro_step 1）：
- 标准版 raw_loss = 0.1602（sum/37）
- 优化版 raw_loss = 0.5927（mean/1），scaled_loss = 0.1482（÷4）
- 差异显著

### 2.2 次要问题：single micro 梯度数值差异

即使 single_micro（无梯度累积）loss 值完全相同，梯度仍有差异：
- micro_step 1：raw_loss 均为 2.8843894，但梯度 max_abs=0.00299（阈值 0.0001）
- 原因：标准版 forward 计算完整 logits 后由 loss function 内部 shift+gather；优化版用 `logits_to_keep` 让模型只计算监督位置 logits
- 数学上等价，但 `logits_to_keep` 通过 slice 实现，计算图不同，bfloat16 下产生数值差异
- 此差异量级（~3e-3）在 bfloat16 训练中可接受，但严格等价性测试不通过

### 2.3 修复方案

已修改 `code/cmj/route1_qwen38_train_sarol_memopt_v1.py`：

1. `self.model_accepts_loss_kwargs = True` — 让 Trainer 传入 `num_items_in_batch`
2. `compute_loss` 中：
   - 当 `num_items_in_batch` 不为 None：`reduction="sum"` 然后除以 `num_items_in_batch`（与标准版完全一致）
   - 当 `num_items_in_batch` 为 None：`reduction="mean"`（与标准版无累积路径一致）

修复后，loss 归一化应与标准版完全一致。single micro 的梯度数值差异（~3e-3）是 bfloat16 精度问题，需要讨论是否放宽阈值或改用 float32 计算 loss。
