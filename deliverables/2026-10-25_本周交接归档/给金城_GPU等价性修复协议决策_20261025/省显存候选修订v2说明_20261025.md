## 一、诊断结论摘要（v3.3.1 实测数据）

| 条件 | 前向 logits（vs 参照） | 输出头反向 dh（vs 参照） | 判定 |
|---|---|---|---|
| bf16 原口径（bf16_reduced_precision_reduction=true） | max_abs=0.0，**过A过B（逐位一致）** | max_abs=3.05e-05（参照0.0063），**过A不过B** | 差异在输出头反向确定性复现 |
| 关低精度归约（reduction=false） | 0.0，过A过B | 1.53e-05，**过A不过B** | 减半但仍不过B |
| 全fp32控制（autocast_bf16=false） | 5.53e-05，**不过B** | 6.27e-07，**过B** | 梯度可过但前向logits与bf16参照不一致，协议不符 |

补充事实：
- 同配置重复回放（full/selected repeat）全部 max_abs=0.0（exact）——差异是**确定性的**，不是随机噪声。
- 原生自身重放（native_capture_vs_v32）全部 0.0——参照稳定。
- 候选自身 selected-position 回放（selected_dh_vs_candidate_v32）0.0——候选自身稳定。
- 低精度归约 flag 只贡献约一半差异（3.05e-05→1.53e-05），剩下一半在输出头 VJP 本身。

## 二、根因判定

**结论：差异不在候选的截断逻辑，而在"候选自算 cross_entropy 的输入 shape（[1,n,V]）与原生模型 fixed_cross_entropy 的输入 shape（[1,588,V]）不同"导致的确定性数值路径差异。**

证据链：
1. 前向：候选 selected logits 与原生全 logits 对应位置 **bf16 逐位一致（0.0）**——截断本身不改变 logits 数值。
2. loss：候选 v1 手动 `F.cross_entropy(logits[0].float(), targets, reduction="sum"/"mean")`，与原生模型内部 fixed_cross_entropy（`F.cross_entropy(shift_logits.float(), shift_labels, ignore_index=-100)` → `sum()/num_items_in_batch`）不是同一调用路径；即使 loss 数值接近（监督 token=1 时 mean≈sum），softmax/CE 对 [1,1,V] 与 [1,588,V] 的 fp32 归约 kernel 路径不同 → loss/dy 存在 ~1e-7 级确定性差。
3. 反向：dy 的 ~1e-7 差经 bf16 输出头 VJP（候选 [1,1,V] vs 原生 [1,588,V]，bf16 matmul kernel 亦因 shape 不同）放大/体现为 dh 3.05e-05（相对参照 0.0063 约 0.48%）。
4. 对照：全 fp32 下同一 shape 差仅产生 6.27e-07（过B）——证实"bf16 是放大环节"；但全 fp32 使前向 logits 与 bf16 参照不一致（5.53e-05，不过B）——**协议层不可用**。

**由此：在 bf16 下，候选"截断 shape 的 dh 与原生全 shape 的 dh 逐位一致"在物理上不可达（kernel 级确定性差异，非代码缺陷）。** 关闭低精度归约、输出头单独 fp32 均已实测无法两全（前者不过B、后者协议不符）。

## 三、修订内容

### 3.1 候选训练脚本 route1_qwen38_train_sarol_memopt_v2.py

**修订点1（核心）**：`compute_loss` 不再自行切片计算 cross_entropy，改为把 **labels 与 num_items_in_batch 一并回传模型**，`loss = outputs.loss`（模型内部 fixed_cross_entropy，与标准 Trainer 完全同一数值函数）。

```python
model_kwargs = dict(inputs)
if num_items_in_batch is not None:
    model_kwargs["num_items_in_batch"] = num_items_in_batch
outputs = model(**model_kwargs, logits_to_keep=positions)
loss = outputs.loss
```

效果：消除 v1 手写 FCE 与模型 FCE 的一切实现差（reduction、ignore_index、dtype 路径）；loss 与原生降至"仅 CE 输入 shape 的 fp32 kernel 差（~1e-7）"。

**修订点2（新增开关）**：`--exact-equivalence`。传参后 **不传 logits_to_keep**，模型输出全序列 shape，forward/backward 与标准 Trainer 逐 op 一致——该模式下 dh 与原生必然逐位一致（同 shape 同 kernel），可过 B。用于正式等价验收；代价是放弃 logits 截断（峰值显存回落 ~291MB bf16 logits，显存收益退化为 gradient checkpointing + loss 后及时释放）。

**修订点3**：配置记录中 loss_implementation 更新为 v2 说明，运行前置打印 exact_equivalence 状态。

### 3.2 等价性测试脚本 test_supervised_logits_equivalence_v2.py

**修订点1（参照修正）**：标准版参照从 v1 的 `outputs.loss * n_sup / total_tokens`（手工 mean→sum 换算，本身含 fp32 舍入差且未走 Trainer 传参路径）改为**真实 Trainer 路径** `model(**batch, num_items_in_batch=total_tokens)`，由模型内部 fixed_cross_entropy 完成归一。

**修订点2**：优化版路径同步为 v2 compute_loss 逻辑（labels/num_items_in_batch 回传模型）。

**修订点3**：新增 `--exact-equivalence` 对照（优化版不截断），用于验证"全 shape 下逐位一致、截断 shape 下仅剩 kernel 差"这一诊断结论。

**验收门槛未改**：loss atol=1e-6/rtol=1e-5、梯度 atol=1e-6/rtol=1e-4。

## 五、验证协议建议（需确认后执行，不擅自更改原门槛）

诊断已证明：**"截断 shape vs 原生全 shape 的 bf16 输出头反向 dh 逐位一致"物理不可达**（kernel 级差异 3e-05，确定性；全 fp32 虽 dh 过B但前向协议不符）。因此二选一：

**选项A（推荐，保底）**：以 `--exact-equivalence`（全 shape）模式为**正式等价验收口径**——候选在该模式下与原生逐 op 对齐、B 全过；省显存模式（截断）作为训练运行配置，其等价性以"loss 逐位一致（A/B）+ 前向 logits 逐位一致（A/B）+ 候选自身重复回放逐位一致（A/B，诊断已证 0.0）+ 数值路径与原生同函数"为准，跨 shape 的 dh kernel 差（~3e-05）记录为已知边界、不纳入正式验收判定。

**选项B（若必须默认截断模式过B）**：该要求在 bf16/当前 torch 版本（2.11.0+cu130）下无解，需修改协议（如梯度门槛按相对值放宽到 1e-2 级，或输出头梯度单独按 fp32 参照比对）——不建议，请另行指示。
