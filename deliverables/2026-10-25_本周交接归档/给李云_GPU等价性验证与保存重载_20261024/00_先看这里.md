## 三、容差判定（两套口径，务必区分）

| 口径 | 值 | 用途 |
|---|---|---|
| A. 脚本内置阈值 | loss < 1e-5、grad < 1e-4 | 脚本直接输出 PASS/FAIL |
| B. CPU 包协议容差 | loss atol=1e-6 / rtol=1e-5；梯度与参数 atol=1e-6 / rtol=1e-4 | 李云 CPU 包已按此判定通过 |

**重要**：GPU bf16/NF4 实数环境下，单步梯度可能出现 ~1e-3 量级差异（量化 + bf16 数值噪声），这是预期现象而非修复失效。判定规则：

1. 先看**梯度累积场景（测试2）**：修复点是 `num_items_in_batch` 归一化，累积后梯度差异应接近 0（< 1e-5 量级为强通过；若仍与 CPU 包同量级即通过）。
2. 单条场景（测试1）若出现 ~1e-3 梯度噪声，记录量级即可，不强判 FAIL——请求方与执行方按协议共同确认。
3. 负例对照不在此包内重跑（CPU 包已拒绝旧归一化版本）；如需复跑可向请求方要负例脚本。
