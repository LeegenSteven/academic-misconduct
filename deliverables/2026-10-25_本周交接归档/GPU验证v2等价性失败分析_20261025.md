# GPU验证v2等价性失败分析（20261025）

包：`cmj_gpu_validation_v2_20261025_handoff.zip`（sha256 清单198项，抽查7项全匹配）
A100（NVIDIA A100-PCIE-40GB）｜torch 2.11.0 / transformers 5.8.0 / peft 0.21.2
27B/NF4（Qwen3.8-27B，4-bit nf4 + bf16 compute + double quant），LoRA r=16/alpha=32，512个可训练tensor

---

## 一、总体结论

**修复候选trainer（SupervisedLogitsTrainer）与原生Trainer在GPU bf16/NF4实数环境下数值不等价，等价性未建立。**

5个case（single_micro / accum4_tail1 / padded_accum4_tail1 / production_accum16_tail13 / eos_as_pad_accum4_tail1）全部未通过A、B两套容差，exit_code=1。这不是"GPU量化噪声量级"的预期偏差（脚本与请求包均声明bf16/NF4单步梯度噪声预期为~1e-3量级），而是**结构性梯度路径差异**：实测初始梯度绝对差异达 **0.02–0.09**，超出预期噪声2个数量级。

|---|---|---|---|---|---|---|---|

| accum4_tail1 | 4 | 否 | 0.0 | 0.0205 | 0.2344 | 0.0114 | 0.000399 |

容差对照（全部超差）：
- A口径：loss < 1e-5、grad < 1e-4 → 5个case的`passed_A_loss_gradients`全部 false，梯度tensor 0/512通过（single_micro），最高也只有172/512（production micro0）
- B口径：loss atol=1e-6/rtol=1e-5、tensor atol=1e-6/rtol=1e-4 → 梯度与参数`passed_B`全部 false，5个case含参数判定全部失败

差异tensor分布：512个全为 `lora_A/lora_B` 权重（q/k/v/o/gate/up/down_proj），无偏置、无norm参数。

## 三、关键观察（证据链）

1. **micro0（第一个优化步前的第一个micro）：loss逐位一致（max_abs=0.0），但梯度已有显著差异（0.0068–0.0859）**。
   同一权重快照（脚本每分支前`p.copy_(initial[n])`重置）、同一输入（`same_execution=True`、batch_sha256一致）、同seed（set_seed(42)），前向数值完全一致而梯度不一致 → **差异必然来自backward数值路径，而非数据、权重初始化或前向计算**。

2. **梯度差异随优化步单调放大**：
   - single_micro：0.0859 → 1.656 → 9.547 → 0.042 → 3.078（micro0-4，5个optimizer step）
   - production_accum16：0.0068 → 0.1320（29个micro，2个optimizer step）
   - loss差异：micro0=0 → micro1≈3.9e-5 → 后续放大到 0.0002–0.2137
   - 参数更新差异线性累积：single_micro 5步 = 2.0e-4, 4.0e-4, 5.7e-4, 7.2e-4, 8.7e-4（≈+2e-4/步）

   动力学符合"微小初始梯度差异 → Adam每步映射为权重差异并累积 → 权重分歧 → 前向loss分歧 → 梯度分歧再放大"的反馈循环。

3. **padding场景差异更大**：items同为37的三个case中，无padding accum4梯度差0.0205 < padded 0.0303 < eos_as_pad 0.0254；但**无padding的single_micro（10 tokens）差异最大（0.0859）** → padding/EOS不是唯一来源，基础backward路径即不等价。

## 四、根因定位（代码级）

两版trainer的loss前向数值一致（micro0逐位相同），但计算图与梯度路径不同：

| 项 | Standard（原生Trainer） | Fixed（修复候选SupervisedLogitsTrainer） |
|---|---|---|
| logits | 全序列logits（transformers 5.8 fixed_cross_entropy路径） | `logits_to_keep=positions` 只保留监督位置（第78-120行） |
| loss | 原生compute_loss + num_items_in_batch（sum/有效token数） | 手动 `F.cross_entropy(..., reduction="sum") / num_items_in_batch`（第109-115行） |
| 梯度 | 全序列CE反向（忽略位置不贡献） | 仅监督位置CE反向 |

数学上两者等价，但 **bf16/NF4实数环境下"全序列bf16 logits→float()"与"只保留监督位置logits"的反向传播浮点路径不同**，产生0.0068–0.0859的初始梯度差（非1e-3量级量化噪声，超出约2个数量级）。该差异与`num_items_in_batch`归一化修复点（累积场景应接近0差异）不是同一来源——**修复点本身逻辑正确（loss数值逐位一致），但修复版采用的`logits_to_keep`梯度路径与原生Trainer不等价**。

注：以上为基于结果文件+源码的证据性归因；精确定位到哪条算子引入差异（如`logits_to_keep`位置索引的bf16精度、`float()`时机、CE在keep维度的reduction顺序），需要额外的最小化实验确认（见下）。

## 五、对项目状态的影响

- GPU数值等价性验证项：**未通过**（EQUIVALENCE_NOT_ESTABLISHED，5/5 case失败）
- 训练保存+独立重载：管线跑通（新adapter sha256 `69063d70...`；512-token重载32条有效，acc 0.53125；64-token原重载32条INVALID保留）
- 与CPU等价性对照：李云10/20回传CPU通过——CPU上是fp32/bf16路径，GPU上是bf16+NF4量化路径，**两者不能互相覆盖**；本次GPU失败是独立问题
- 任务书"修复候选与原生Trainer数值等价"验收项：**仍不满足**；32条冒烟训练闭环状态不变

## 六、下一步选项（建议按序）

1. **最小化根因实验**（约1-2h A100）：构造同一batch，分别用 a) 原生Trainer、b) 修复版完整路径、c) 修复版但去掉`logits_to_keep`改为全序列logits+sum/N、d) 修复版`logits_to_keep`但loss用mean 四路对比第一步梯度——直接定位是`logits_to_keep`还是`sum/N`还是`float()`时机导致的差异。
2. **若确认`logits_to_keep`路径是根因**：评估是否可接受在训练脚本中改为"全序列logits（复用`outputs.logits`）+监督位置targets+sum/N"——以牺牲监督位置显存优化为代价换取与原生Trainer数值等价（该方案仍可借助`logits_to_keep`的显存收益之外保持全序列等价路径的版本）。
3. **协议层面**：按请求包"GPU bf16/NF4噪声预期1e-3"口径，当前0.02–0.09的差异是否可被双方重新界定为"可接受"——**不建议**，因为差异随步数放大且影响训练轨迹，不是单步噪声。
4. 在根因确认前，**不修改原冻结trainer字节、不改gold/Test、不重跑模型**；本包已完整保留原失败记录与两版源码（original/与code/cmj/）。
